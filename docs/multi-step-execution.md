# 多步执行与进度恢复

多步任务继续使用同一个 Agent 的模型与工具循环。模型说明当前步骤与关键进展，读取材料、执行工具，再根据结果决定下一步。缺材料或工具失败时，它应说明已经完成什么、缺什么以及继续需要什么，不能把部分完成说成全部完成。简单问题直接回答。

例如核对提交、里程碑和风险：提交和风险材料可读、里程碑文件不存在时，助手应报告已核对的进展和风险，以及缺少的里程碑材料。补齐文件后，在同一会话输入“继续”；已退出程序则先运行 `minipi -c`，再输入补充信息。

## 保存发生在什么时候

1. CLI 先保存用户输入，再开始调用模型。
2. Agent 收齐一轮模型回复并执行其工具调用。每个工具结果仍即时显示。
3. 全部结果进入上下文后，Agent 发出 `step_end`；CLI 等待 `session.save()` 完成，再让循环进入下一次模型请求。
4. 没有工具调用、模型错误或正常中断时，整次调用结束，CLI 保存最后的回复。

`step_end` 表示一批调用与结果已完整进入上下文，不表示业务任务完成。工具错误、输出截断的错误结果，以及中断后为未执行调用补齐的结果，都按完整批次保存。`turn_end` 仍表示整次 Agent 调用结束。

存储沿用按工作目录区分的 JSONL 会话。正常保存追加新消息；压缩更换消息数组后，用临时文件完整写入再替换。没有额外的计划文件、规划工具或任务数据库。[会话位置与命令](./sessions.md)

## 失败和恢复的边界

中途保存失败会显示 `会话进度保存失败` 警告，工具结果留在内存中，执行继续。下一次批次保存或最终保存会重试未保存的消息；最终保存仍失败则报告错误。输入保存失败时继续沿用原行为：报告错误，本次不调用模型。

恢复保证仅针对已成功保存的完整记录。正在执行的工具批次、未保存的消息和写入过程中强退不在保证范围；文件和命令的外部副作用不会随会话回滚。续聊由用户再次输入触发，模型可以重新核对资料，不承诺每个操作只执行一次。

## 验证

`npm test` 覆盖完整批次的事件顺序、输出截断、工具期间中断、执行中退出后续聊，以及中途保存失败后的补写。CLI 测试在下一次模型请求时直接退出进程，验证此前的消息和工具结果已保存。

真实模型验收使用临时资料和独立个人目录，不写入用户的真实会话或知识库：

```sh
node --env-file=.env --import tsx test/multi-step-e2e.ts
```

它分别验证缺少里程碑材料时的报告、补材料后续聊及简单问题直接回答。固定模型回复的自动化测试验证保存机制，真实模型轨迹验证进度说明和缺口判断。
