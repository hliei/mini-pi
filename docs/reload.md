# Reload

技能清单和长期偏好在不同的时机刷新。下一条普通输入到来时，CLI 分别比较它们与会话里同类的上一版。有变化才在用户消息前追加一条完整的系统消息。OpenClaw 也在历史末尾传递会话中途发生的变化。[OpenClaw 提示缓存](https://docs.openclaw.ai/reference/prompt-caching)

| 内容 | 何时读取 | 变化怎样进入请求 |
| --- | --- | --- |
| 技能清单 | 启动时扫描，会话中输入 `/reload` 再扫描 | 追加最新完整清单，技能正文在任务匹配时用 `read_file` 读取 |
| 长期偏好 | 每个新用户回合开始时读取 `~/.minipi/MEMORY.md` | 追加最新完整偏好，文件被删除或清空时追加空偏好 |

首轮依次发送固定提示、技能清单、长期偏好和用户输入。后续两项同时变化时也按技能、偏好的顺序追加。固定提示包含记忆写入规则，偏好正文有自己的消息位置。

## 当前会话怎样刷新技能清单

假设你已经在 Mini-Pi 里聊了几轮。现在另开终端创建 `~/.minipi/skills/release-notes/SKILL.md`。回到原聊天直接说“整理发布说明”，模型看到的技能清单仍然是启动时那一份。输入 `/reload`，再说“整理发布说明”，模型就能看到新增描述，按需用 `read_file` 读取正文。旧聊天仍在。

内置的 `weekly-report` 启动时就可用。用它做同样的实验时，可以在另一个终端新增同名个人版。刷新前清单指向内置文件，刷新后指向个人文件。[技能格式与目录](./skills.md)

### 一次刷新怎样进入请求

1. CLI 启动时扫描两个目录，打开技能文件解析头部，取名称、用途和绝对路径，按名称排序。模型首先只看到清单，调用 `read_file` 后才看到正文。
2. `/reload` 重新扫描，成功后替换进程中的清单并恢复输入。命令本身不触发模型调用。若整个目录扫描失败，终端显示原因，当前会话仍可使用上次成功扫描的清单。
3. 收到下一条普通输入时，CLI 比较新清单和会话里最近一条技能系统消息。更新与用户输入在请求模型前一同保存。连续刷新多次，以发出输入时的最终清单为准。[清单生成](../src/skills.ts) · [CLI 输入处理](../src/cli.ts)

```text
第一次请求    system 固定提示 | system 技能 A | system 当前偏好 | user 问题一
/reload      本地清单新增技能 B
下一次请求    完整第一次请求 | assistant 回复一 | system 技能 A、B | user 问题二
```

比较以整段技能清单为单位。增加、删除、修改描述或切换文件路径，都会改变这一段。删去 B 后，下一条更新只列 A。清单变空时，更新写入空列表。只改已有文件的正文，清单仍然相同，下次匹配任务时 `read_file` 会读到磁盘上的新正文。

## 偏好自动生效时的请求顺序

第十轮用户说“以后周报先写风险”。模型调用 `edit`，收到工具结果后回复。第十轮内的工具调用仍沿用回合开始时的偏好。第十一轮收到用户输入时，CLI 才读到新版本，无需执行 `/reload`。

```text
第十一轮请求 = 截至第十轮回复的全部消息 | system 最新完整偏好（取代旧版） | user 第十一轮输入
第十二轮请求 = 完整第十一轮请求 | assistant 第十一轮回复 | user 第十二轮输入
```

若文件被删除或清空，下一条偏好消息明确说明当前为空。旧偏好仍留在历史位置，当前任务采用最近版本，并优先执行用户当次的明确要求。[偏好读写](./memory.md)

## 恢复会话和复用前缀

`minipi -c` 从 JSONL 恢复两类系统消息的位置。下一条输入到来时，CLI 将启动时发现的技能和当时读到的偏好分别与历史比较。旧会话从未记录过偏好段时，从本轮起追加当前版本。压缩旧聊天时，程序将被压缩部分最后一份技能清单和最后一份偏好按原顺序放在摘要前，近期消息里的更新仍在原处。[会话读取](../src/session.ts) · [上下文压缩](../src/agent.ts)

Mini-Pi 把中途的 `system` 按原位置发送给 OpenAI 兼容接口。验收比较发给模型的消息数组，包括工具调用、工具结果、更新和用户输入。上下文压缩会重组历史，因此从压缩后的请求开始比较前缀。实际缓存命中量取决于服务商、模型和请求。[请求转换](../src/llm.ts) · [请求顺序回归测试](../test/skills.test.ts)

## 如果以后支持刷新工具

目前 `/reload` 只刷新技能清单，内置工具在启动时注册。假设以后允许在会话中增加一个工具，刷新时需要同时更新本地可执行的工具和下一次请求的 `tools` 字段。模型通过这个字段看到工具名称、说明和参数。即使聊天消息的前缀相同，工具定义也可能影响服务商的缓存命中。[CLI 工具初始化](../src/cli.ts) · [工具执行](../src/agent.ts) · [模型请求](../src/llm.ts)

## Pi 的实现

Pi 在启动或执行 `/reload` 时发现资源，在下一次请求前按提示词段落比较变化。Pi 还会针对不支持中途系统消息的模型把更新合并到开头，Mini-Pi 当前要求接口接受对话中的系统消息。[Pi 的技能发现](https://github.com/earendil-works/pi/blob/4afe78de1e51162c01c946dcf080e6a266685a01/packages/coding-agent/docs/skills.md#L41-L49) · [按段比较](https://github.com/earendil-works/pi/blob/4afe78de1e51162c01c946dcf080e6a266685a01/packages/coding-agent/src/core/system-prompt.ts#L212-L227) · [追加时机](https://github.com/earendil-works/pi/blob/4afe78de1e51162c01c946dcf080e6a266685a01/packages/coding-agent/src/core/agent-session.ts#L2058-L2061) · [上游模型适配](https://github.com/earendil-works/pi/blob/4afe78de1e51162c01c946dcf080e6a266685a01/packages/ai/src/utils/transcript.ts#L108-L119)
