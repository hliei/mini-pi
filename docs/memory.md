# 跨会话记忆

在项目 A 告诉 Mini-Pi“我看周报习惯先看风险”。进入项目 B，用 `minipi` 新开会话，只说“写本周周报”。助手会沿用风险优先的顺序，从 B 的材料中取事实。

| 用户的表达 | 当前行为 | 下次新开会话 |
| --- | --- | --- |
| 我看周报习惯先看风险 | 记录长期偏好 | 风险在前 |
| 这次先写进展 | 本次进展在前 | 恢复风险在前 |
| 以后改成先写结论 | 替换之前的周报排序偏好 | 结论在前 |

偏好保存在 `~/.minipi/MEMORY.md`，每行一条。第一次保存偏好时才创建文件。模型根据用户原话判断是否需要长期保存。

每个普通用户回合开始时，CLI 都读取这份文件。首轮把当前偏好作为独立的系统消息放在用户输入前。后续只在内容变化时追加完整的新版本，包括其他终端刚写入的偏好。删除或清空文件后，下一轮会收到“当前长期偏好为空”，先前的版本随之失效。已有聊天里看到过的内容仍保留在会话记录中。

固定的记忆写入规则留在首条系统提示。技能清单通过 `/reload` 手动刷新，偏好在下一轮自动生效。续聊和上下文压缩各自保留两类消息的有效版本。[刷新时机与请求顺序](./reload.md)

在终端可以看到 `edit` 的工具调用及保存结果。新增时追加一行，改口时只替换唯一匹配的旧行。变更先写到同目录的 `MEMORY.md.tmp`，成功后再替换原文件。写入冲突时工具报告未保存，可稍后重试。如果进程在写入中被强制终止并留下临时文件，先退出正在更新偏好的 Mini-Pi，再移除该临时文件，原有偏好仍保存在 `MEMORY.md`。
