# 新开与继续会话

在项目 A 的目录运行 `minipi`，发送一条消息后退出。下次仍在 A 目录运行 `minipi -c`，模型能看到上次的输入和已保存的回复。改在项目 B 运行 `minipi -c`，它只会找 B 的聊天；B 没聊过就从空白开始。工作目录以启动时所在的目录为准，仓库子目录也算另一个目录。

| 命令 | 行为 |
| --- | --- |
| `minipi` | 新开会话，不加载旧消息 |
| `minipi -c` 或 `minipi --continue` | 继续当前目录最后修改的有效会话 |
| `npm run dev -- -c` | 从源码运行时续聊 |

会话文件在 `~/.minipi/sessions/<工作目录路径的 SHA-256>/<UTC 时间戳>_<UUID>.jsonl`。时间戳中的冒号和小数点写作短横线。每行保存一条用户消息、助手消息或[技能清单与长期偏好的系统更新](./reload.md)。只启动或只输入 `/reload`，不会创建会话文件。提交普通输入时先保存本轮的更新与用户消息，再请求模型。执行中每轮模型回复及对应工具结果完整进入上下文后保存，整次调用结束后再保存最终回复。

中途保存失败时警告并继续，后续保存会重试。使用 `-c` 恢复后，输入“继续”或补充材料即可利用已保存记录推进任务；模型可能重新核对资料。正在执行的批次和尚未成功保存的消息不保证恢复。[多步执行与进度恢复](./multi-step-execution.md)

旧版的 `~/.minipi/session.jsonl` 没有目录归属，新版不会读取、迁移或自动删除它。聊天按工作目录保存，同一用户的各个项目共享[长期偏好](./memory.md)。
