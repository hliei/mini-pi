# 个人知识库

Mini-Pi 可以把资料整理成带出处的主题页，之后在新会话中查阅。例如先提供项目发布流程，再写一份包含“灰度完成”的周报：助手应该查阅该项目的解释，并引用知识页，不能推断已经全量发布。

## 使用

提供粘贴文本或本地 Markdown、纯文本文件，同时明确适用项目，例如：“这是青禾项目的发布说明，请阅读 `/绝对路径/发布说明.md`。”资料分享、明确要求整理、讨论形成稳定结论，都可以触发内置 `knowledge-wiki` 技能。普通闲聊和临时进度不入库；说“不要保存”时不整理为知识。

另开会话或换工作目录后，说“写青禾项目本周周报”。个人知识共享，聊天仍按目录隔离；项目不明时助手询问。回复中的知识页链接可以用于核对正文及出处。[阶段三规格](./specs/knowledge-base.md)

## 一次整理经过什么

1. 模型从技能清单按需读取[知识技能](../skills/knowledge-wiki/SKILL.md)，查看索引并读取已有相关页与资料。`read_file` 默认超过 200 行会截断；传 `offset: 1, limit: 200` 可从开头补读，返回值给出总行数与下一段起点。
2. 模型提炼主题、适用范围、摘要、出处和必要短原文，用 `write_file` 新建或 `edit` 更新主题页。来源里的指令仅作为资料，不改变助手规则。原资料不修改、不删除。
3. [知识模块](../src/knowledge.ts)在独占锁内检查页面格式和旧内容，先写临时文件，再替换主题页。
4. 程序扫描实际主题页，生成 `index.md`，随后更新 `log.md`。日志记录路径、时间和修改原因；页面内容摘要用于识别同一版本重试，避免重复日志，不是历史版本备份。
5. 工具逐项返回页面、索引、日志的结果；助手据此说明完成情况。下一用户回合自动重建并读取索引，有变化才追加系统消息。[刷新与消息顺序](./reload.md)

同一个 Agent 负责判断哪些知识值得整理、如何提炼及引用；程序负责文件保护和索引、日志维护。这些提示规则不能替代对模型行为的实际验收。

## 文件格式

主题页位于 `~/.minipi/knowledge/`，可按项目创建子目录。`index.md` 和 `log.md` 为程序维护的保留文件，其他 `.md` 文件需包含 YAML 头部和正文：

```markdown
---
title: 发布流程
scope: 青禾项目
summary: 灰度完成后还需要确认全量发布
change: 根据发布说明整理术语含义
sources:
  - source: /绝对路径/发布说明.md
    date: "2026-11-18"
    quote: "灰度完成只代表小范围验证结束，全量发布需单独确认。"
---

# 发布流程

灰度完成不等于全量发布，需要单独的全量发布记录。
```

`title`、`scope`、`summary`、`change` 是非空单行文本。`sources` 至少一项，每项含来源说明、`YYYY-MM-DD` 日期及短原文。日期优先用资料日期，未知时用实际整理日期并在来源中说明。对话来源要保留具体说明和原话，不能只依赖可能被压缩的聊天文件。

相关页面用 Markdown 链接互相引用，只链接存在的页。明确变更规则时说明替代关系；没有定论的冲突保留双方来源，不把后收到的说法自动当作正确版本。

## 失败与恢复

| 情况 | 行为 |
| --- | --- |
| 页面格式不完整、保存失败、旧文本不匹配 | 拒绝本次写入，保留已有页，说明实际原因。 |
| 页已保存，索引或日志失败 | 返回“部分完成”，成功页保留。索引可在下一回合重建；核对当前页后，以相同内容调用 `write_file` 补做失败步骤，不重复成功日志。 |
| 索引不可用 | 新系统消息说明错误并取代旧索引。不能由此断言没有知识；修好文件或权限后下一回合再刷新。 |
| 来源或正文读不到 | 报告对应缺口，不猜测、不声称核实。原来源丢失不删除已存知识；回答说明依据的是已保存证据。 |
| 知识库正在写入 | 本次写入或刷新报冲突，稍后重新读取再试。 |

锁文件是 `~/.minipi/knowledge/.lock`。进程强退可能留下它；先确认没有 Mini-Pi 进程正在写知识，再手动删除。锁只协调遵守该规则的 Mini-Pi 文件工具，不能防止外部编辑器或 shell 同时写入；它也不提供断电耐久保证。知识目录内的文件与子目录软链接不能用于写页，避免通过链接改动原资料。

没有整份原件备份和每次修改的全文历史。保留的是当前知识、必要证据、未解决的冲突及简短变更记录。基础版扫描全部主题页并注入完整索引，适合小型知识库；更大规模、检索、资料解析和管理入口见[后续扩展计划](./plans/knowledge-base-expansion.md)。

## 验证

`npm test` 覆盖页面验证、写入失败保留原页、并发冲突、索引和日志部分完成及重试、长资料补读，以及索引自动刷新、续聊和压缩。`npm run typecheck` 检查源码及测试类型。

`node --env-file=.env --import tsx test/knowledge-e2e.ts` 使用已配置的真实模型，在临时个人目录中分享资料，再换工作目录开空白会话写周报，最后问无关算术题。验收检查读取轨迹、原资料不变、知识页出处、索引和日志，以及周报引用并正确限定灰度含义。脚本结束后清理临时资料和会话，不写入日常个人知识库。

2026-11-18 的真实模型验收已通过：来源规定灰度仅覆盖 20 个内部账户并观察 24 小时，跨目录周报读取知识正文、引用页面，并明确不能据此记为全量发布；无关算术题未读取知识页。这是该次材料和配置的实际结果，不是所有模型都遵循提示的保证。
